ドライブ実況ワイプ 検証版

保存済みの設定でそのまま台本を作り、できあがったら再生に入ります。音声は再生しながら作られます。 公開動画のみ対応します（限定公開・非公開はGemini側が受け付けません）。

動画

まずは10分程度で試すのを勧めます。長時間を一度に投げると無料枠（1日8時間）をすぐ使い切ります。

実況

景色に変化がなく、語ることがない区間で、間を持たせる独り言として使われます。
見どころが続く区間では差し込みません。頻度は区間あたり1〜2回までです。

登録したフィードから新しい記事を拾い、興味・関心のURLと同じように要約と感想を作って残します。 読んだ記事は character/reads/ に貯まり、次の台本から雑談の材料になります。同じ記事は読み直しません。
人気順は、RSSに人気の情報が入っていないため、そのサイトの人気順・ランキングのページを登録したときに効きます。 通常のRSSでは新着順になります。

興味・関心にnoteなどのURLを貼っておくと、その記事を読んで感想を作り、欄に書き足します。 以降はその感想が雑談の材料になります。読むのはGeminiで、1つのURLにつき1回だけです。 台本生成の前にも自動で走ります。
キャラクター設定・興味・関心・フィードは、データリポジトリを設定していれば起動時に自動で読み込まれます。 手元での書き換えを残したいときは、詳細設定「データ」タブの「まとめて保存」を押してください。

実況＝目の前のもの・標識・場所についての発話。雑談＝独り言や連想など、映っているものに依らない発話。
上限であり目安でもあります。上げると細かい対象（歩行者・看板の文字・空の色・音）まで拾い、下げると大きな変化だけに絞ります。
見どころが続く区間では雑談が減り、何もない区間では実況が減って雑談が埋めます。
信号での停止・発進は、その操作自体を実況しません。ただし信号待ちは雑談に向くので、独り言は入りえます。

コメント欄（任意）

YouTube用のAPIキーが必要です（設定のステップ3）。日本語コメントのみ抽出します。
視聴者同士のやり取りは、上限まで読み上げてからスレッド全体に1回だけ反応します。超えた分は省略されます。

データリポジトリを設定していれば、できあがった台本は自動で保存され、「保存済みから選ぶ」に並びます。

音声

同じPCで使うなら空欄のままで動きます。スマホなど別の端末から使う場合は、PC側で cloudflared tunnel --url http://127.0.0.1:50021 を実行し、表示された https://… をここに貼ります （このページはHTTPSのため、http://のLANアドレスはブラウザが拒否します）。 エンジンは --allow_origin https://kyunkyunpeachdisco-maker.github.io 付きで起動してください。

Gemini音声とは別のサービスです（Cloud Text-to-Speech）。無料枠は WaveNet・Standardが月400万文字、Neural2・Chirp3が月100万文字で、 ドライブ動画1時間ぶんの台本でも2万文字程度なので、実質使い切れません。
手順：① Cloud Text-to-Speech API を有効化 → ② APIキーを発行 → ここに貼る。
YouTubeのキーと同じプロジェクト・同じキーが使えます（キーに「APIの制限」を掛けている場合は、そこにCloud Text-to-Speech APIを追加してください）。 プロジェクトに請求先アカウントの紐付けを求められることがありますが、無料枠の内側なら請求は発生しません。

Gemini音声は上から穏やか → 明るい → 力強い → 説明向きの順に並べてあります。 括弧内は公表されている声の特徴です。「声を確認」で聴き比べてください。
落ち着いた独り言なら Achernar Vindemiatrix Callirrhoe あたりが合います。

Gemini音声の無料枠は1日あたりの生成回数がかなり少なく、台本1本ぶんを賄えないことがあります。 上限に当たった場合は待っても同じ日のうちは空かないので、「Google Cloud音声」に切り替えてください（同じくらい自然で、無料枠は桁違いに大きく、スマホからも作れます）。 生成した音声は端末に保存されるため、同じセリフを作り直して枠を減らすことはありません。

アバターの調整

上が実際のワイプです。下の設定を変えると、ここにそのまま反映されます。
VRMを選んだ時点で、体格に合わせて自動で画角を決めます。 ワイプの形や横からの角度を変えた後は「自動で合わせる」でやり直せます（手で変えた値は初期値に戻ります）。

ハンドルの入れ具合は、体とハンドルのどちらを画面の中心に置くかです（0で体、1でハンドル）。 画角は「頭＋肩」「ハンドルまで」が入る距離を自動で計算します。寄りは倍率（小さいほど寄る）、 上下位置は人物を画面のどこに置くかです。設定は保存されます。
「ハンドルまで映す」を選ぶと腕とハンドルが出ます。ハンドルの位置を先に決め、手はその縁を掴みにいきますので、 まず大きさ・傾き・高さ・前後でハンドルを置いてください。腕は自動で追従します。 手を握る位置は左が9時15分・中央が10時10分・右が11時5分、肘の張り出しは肘を外に開く量です。
VRMを選ばない間は、動作確認用の簡易アバターが表示されます。

VRMファイルはどこで手に入れる？

まずは配布モデルを1つ落として試すのを勧めます。自作は時間がかかるので、 画角や動きが好みに合うか確かめてからで十分です。

選ぶときの目安

  1. 軽いモデルを選ぶ。ワイプは小さいので高精細は不要で、重いとiPhoneが発熱します
  2. 胸から上が作り込まれているもの。この画角では顔と上半身しか映りません
  3. VRM 0.x でも 1.0 でも読めます。背中を向いたら「向きを反転」で直ります

ライセンスの見方

  1. 配布ページの利用条件が「設定されていません」の場合、それは許可ではなく未設定です。 商用利用・改変・再配布は許可されていないものとして扱ってください
  2. 自宅で個人的に見るだけなら、通常はダウンロード時に同意する利用規約の範囲です
  3. VRMファイルをこのリポジトリに入れないこと。公開されるため再配布にあたります。 このアプリは端末内（IndexedDB）に保存するだけなので、そのまま使えば問題ありません
  4. 「親作品」がある二次利用モデルは、元の作者やキャラクターの権利も重なります。 公開する予定があるなら、条件が明記されたモデルを選ぶほうが安全です

実写にしたい場合：VRMは基本的にアニメ調です。実写寄りにするなら、 写真と音声から動画を作って読み込む方式が必要になります（未実装）。

再生

「音声をまとめて用意」を先に実行すると、再生中に音声を作らないため利用上限に当たりません。 作った音声は端末に保存され、同じ台本の2回目以降は生成なしで再生できます。
iPhoneでは最初の再生に画面のタップが必要です。この「再生を開始」がその操作を兼ねています。

台本

台本ジェネレーターで保存したJSONを読み込んでください。

データリポジトリ（端末間の受け渡し）

まとめて保存＝キャラクター（設定・興味・フィード）＋アバター（VRM・調整値）＋読み込み中の台本と用意済みの音声。
まとめて読み込む＝キャラクター＋アバター＋この台本の音声。台本そのものは上部の「保存済みから選ぶ」から開きます。

PCで作った音声をスマホで鳴らすための置き場です。台本と音声をあなたのプライベートリポジトリに保存し、別の端末で取り込みます。 取り込んだ音声はエンジンの設定に関係なく再生されるので、スマホに内蔵音声しかなくてもPCで作った声で鳴ります。 台本の保存・音声の取り込みは自動で行われます（台本は生成時、音声は「まとめて用意」後と台本の読み込み時）。 取り込み直したいときだけ「まとめて読み込む」を押してください。

初回の準備（3ステップ）

ステップ1：プライベートリポジトリを作る
このリンクから作成（名前と非公開が入力済み）
「Create repository」を押すだけです。すでに使いたいリポジトリがあれば、この手順は飛ばせます。

ステップ2：Fine-grained トークンを発行する
このリンクから発行（Token nameが入力済み）
Token name の例は drive-wipe です。次の3つを設定してください。

  1. Expiration：90 days か Custom→1年後（切れたら再発行して貼り直すだけです）
  2. Repository access：Only select repositories → ステップ1のリポジトリを選ぶ
  3. Repository permissions：Contents: Read and write だけ

「Generate token」を押し、表示された github_pat_… をコピーします。 この画面を閉じるとトークンは二度と表示されません。

ステップ3：上の2つの欄に入れて「保存」
複数の端末で使う場合は、同じ2つを各端末で入力してください。
初回の保存時に、リポジトリへ案内ファイル（CLAUDE.md）を自動で作成します。これがあると、 claude.ai/code でこのリポジトリを開いたときにデータの場所と構造が伝わり、台本の書き換えを頼めます。 すでにCLAUDE.mdがある場合は何もしません。

保存済みの台本

データリポジトリに保存した台本を選ぶと、読み込んで再生します。

セットアップ

キーはこの端末のブラウザ内（localStorage）にのみ保存されます。送信先はGoogleのAPIだけです。

1Gemini APIキー（必須）

  1. Google AI Studio のAPIキー画面を開く
    https://aistudio.google.com/apikey
  2. 「APIキーを作成」を押す
  3. プロジェクトを選ぶ画面が出たら 新しいプロジェクトで作成 を選ぶ
    既に使っているCloudプロジェクトがあればそれでも構いません。迷ったら新規で。
  4. 表示された AIza… をコピーして下に貼る

無料枠あり・カード登録不要。ただし動画の解析は1日8時間までです。
キーは後からでも同じ画面で再表示できるので、控えを取り損ねても大丈夫です。

新規と既存、どちらを選ぶべきか

新規を勧めます。無料枠はプロジェクト単位なので、専用にしておけば他の用途と枠を食い合いません。 不要になったらプロジェクトごと消せますし、有効化するAPIもこのアプリの分だけで済みます。

新規で作ると gen-lang-client-0123456789 のような自動生成の名前が付きます。 ステップ3でこの名前を選ぶ必要があるので、控えておいてください。

2モデルを選ぶ

既定のまま試して動けばそれでOKです。
モデル名は頻繁に入れ替わります。エラーが出たら「一覧を取得」で、あなたのキーで今使えるものを確認できます（キーの疎通確認も兼ねます）。

どれを選べばいいか

Flash系を勧めます。ドライブ動画は尺が長く、映像は1秒あたり数百トークンを消費するため、 Pro系だと解析コストが跳ね上がります。台本の面白さは主にキャラクター設定で決まるので、 まずFlashで試して、物足りなければ上位を試す順番が無駄がありません。

一覧には動画を扱えないモデルも混ざります（埋め込み・画像生成・音声など）。 gemini-…-flash か gemini-…-pro の名前のものを選んでください。

3YouTubeのコメント取得（使うときだけ）

YouTube専用のAPIキーを作ってください。 AI Studioで作ったキーは Generative Language API 専用に発行されることが多く、 YouTube Data API を有効化しても、キーの「APIの制限」に追加できないため兼用できません。

  1. プロジェクトを作成する（名前は何でもよい。既存のものでも可）
  2. YouTube Data API v3 を有効にする
    ※画面上部のプロジェクト選択が1のものになっているか確認
  3. 認証情報で「認証情報を作成」→「APIキー」
    ※「サービスアカウントを介してAPI呼び出しを認証する」はチェックしない（チェックすると使えなくなります）
  4. できた AIza… を下に貼って「接続テスト」

Geminiのキーを兼用したい場合

多くの場合できません。AI Studioのキーは Cloud Console の認証情報一覧に現れないか、 現れても「APIの制限」に YouTube Data API v3 を追加できません。試すなら、 キーのプロジェクトで YouTube Data API v3 を有効化したうえで、 認証情報からそのキーの制限に追加できるか確認してください。追加できなければ諦めて上の手順で作ってください。

Cloud Console にプロジェクトが出てこないときは、ログイン中のGoogleアカウントが違うか、 プロジェクト選択ダイアログで「すべて」タブを見ていないのが原因のことが多いです。

無料枠は1日10,000ユニット。コメント取得は1回1ユニットなので、通常は使い切りません。
